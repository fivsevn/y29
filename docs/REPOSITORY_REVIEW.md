检查日期：2026-11-08。基线为 GitHub `fivsevn/y29` 的 `main` 提交 `e936cc9`；本次整理在独立分支中进行。下文区分已修复的代码缺陷与后续需要设计决策的工作。

## 当前状况

仓库是原生静态多项目站点，无第三方运行依赖。阿岚与移动乌托邦已把规则放在 `engine.js`、界面放在 `app.js`；训练游戏将规则、装载数据、控制器与 Canvas 演出放在 `game.js`，内容又分散在四个文件中，是后续维护的主要复杂度来源。

线上首页、阿岚、训练、路西法零、STORYTELLER 可访问。移动乌托邦可直达试玩，但首页保持 OFFLINE。基线的测试、内容同步和 Pages 部署成功，检查时没有打开的 PR 或 Issue。源码与现有测试、工作流、构建输出白名单及资源依赖均已检查；不以此替代所有浏览器、所有操作路径的穷尽验证。

## 下一步怎样深化

建议先处理训练规则的明确欠缺，再逐步分离代码；每一步单独提交、保持当前游玩路径可检查。

| 优先级 | 工作 | 修改入口与完成条件 |
| --- | --- | --- |
| P1 | 明确每项动作的身体部位 | `training/game.js` 的 `doWorkout()` 仅列出 6 个动作的腿／背映射，其余默认肩部；`content.js` 新增的深蹲、臀桥、登阶、下拉等也落到肩部。把部位写为动作数据字段，先决定三部位是否足够，再验证疲劳、恢复和七日平衡 |
| P1 | 分离训练规则和浏览器界面 | 先建立最终组合内容的单一入口，再抽出纯规则模块，最后移动控制器与绘图；保留已有导出或一次更新所有测试和导入，完整周目与浏览器检查均通过 |
| P2 | 合并内容维护入口 | `content.js`、`expansion.js`、`variety.js` 现在按历史扩充批次分组。后续按人物、动作、店铺、日常拆分，建立清晰 ID；迁移前后比较最终目录和可达事件，不顺带改文案 |
| P2 | 给内容扩充增加结构校验 | 目前多处测试锁定总数。增加字段、引用、ID、阶段及实际可达性校验；新内容数量可以变化，重复或错误关系仍会失败 |
| P2 | 决定训练是否需要续玩 | 当前刷新清空是明确行为。若增加存档，先定版本、迁移、随机种子、个人信息和重开范围，再做恢复测试，避免把整个 DOM 或未版本化对象直接存入浏览器 |
| P2 | 决定移动乌托邦的正式发布范围 | 先确认当前原创人物与场景、五结局表达及资源节奏；确认后再同时更新首页与 README 的 OFFLINE 状态 |
| P3 | 扩展长线游戏内容 | 阿岚新增信号、事件或结局时补可执行路径；移动乌托邦扩展夜晚／地点时检查每条天气与资源线；训练新增好友时补出勤、事件、到场表现、聊天与周末反馈 |

阿岚和移动乌托邦的存档都是种子与操作重放。修改旧动作、动作顺序、随机方式或结束条件时，必须先评估存档版本。移动乌托邦保留原始 250 条恢复保护；本次可防止新存档因撤回超限，但既有超限旧档不会自动恢复。
