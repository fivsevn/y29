# 路西法零：AI 运营入口（尚未启用）

本文件定义未来已授权任务的执行方式。它不是开启任务的授权。总开关唯一来源是 [`../publication.json`](../publication.json)，首版为 `automaticPosting: false`。检查发现关闭就停止新内容发布；用户维护或预览请求不等于新增运营回合。

## 每轮读取

1. 最新 `main`、本文件、发布规则与 `publication.json`；不能使用旧聊天代替。
2. `users/registry.json` 的稳定身份、启用状态和 AI 范围。`none` 账号只读。
3. 仓库外的最新人设档案：说话习惯、发布频率、关系、知情范围、禁区，以及事实的确定性和公开性。可用[本地上下文工具](private-profiles.md)汇集，输出仍留在仓库外。
4. `community.md` 的覆盖点，覆盖点之后的全部归档，以及候选话题涉及的旧帖。`posts/` 才是源事实，摘要不能代替历史。
5. 工作分支、待核验批次和近期提交；尚未上线的候选也计入防重，不能因为页面没有出现而再写一份。

## 创作边界

- 先确定本轮稳定批次 ID，恢复时沿用。最多 7 条；没有自然动因时可以零条，不按唤醒次数推进一天。
- 每个发言者都要知道其正在回应的事情。公开回复只能依据公开可见的父帖和其确实知道的前情，不使用全知叙述。
- 【原典】表示已确定，不表示可以公开；【推演】不是原典；【待定】不能当作已发生。秘密身份、重大剧情、未公开情节和内部运营分析不进入正文、简介、图片或提交说明。
- 私有档案缺失或权限/知情边界不明时，不生成该人物的正式日常；可停留在已审核样例，或换成资料充分的候选。不要从名字、头像、MBTI 或单次发言补造稳定人格。
- 允许普通短句、沉默和话题中断，不要求每个人出场，不为每条动态安排包袱、伏笔或情绪升华。说话先回应具体的人和事。
- 新回复用 `replyTo` 关联真正父帖。不要用一条独立动态中的 `@` 代替回复，也不要把多人的发言塞在一篇正文。
- 只追加近期呈现时间，不插入旧时间线伪造前情。演示日期不确立小说故事时间。
- 只有明确授权后才从 `sample` 切换到 `daily`，不要自行扩大 AI 权限、修改总开关、建立自动任务、增加第三方服务或改变其他项目。

## 审核、导入与记忆

按[发布说明](publishing.md)在仓库外准备批次，审查后使用 `--reviewed --ai` 导入。同批重试读取原归档；不要修改 ID 或时间来重发。自动开关与范围会由导入程序检查，但语义上的剧透需要操作者审读。

公开共同记忆只记已在原帖发生、后续有用的小事，包含依据的帖子 ID、相关公开账号与覆盖时间；短期琐事直接读原帖。公开环境也只包含可公开的内容，不记录正在计划的剧情。

人物私有变化只写仓库外档案，保持来源标注，不因一次 AI 推演将其升级为原典。社区回合中的真实运行记录、私有判断与候选计划也只存在于私有存储；公开交接说明不要变成提示词或秘密摘要。

完成时区分：本地候选、已归档、已提交、已合并、已上线。未确认的部署继续核验原批次，不将提交成功写成上线成功。第一版不会自动执行上述运营。
