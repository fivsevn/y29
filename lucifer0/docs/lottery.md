# 抽签规则

本页集中说明额度、机会、终稿要求与恢复语义；现行数值以 [publication.json](../publication.json) 为准。每次更新保存种子与抽签配置，按操作编号、帖号和抽取项目重现结果。创作与审读见[写作与改编](writing.md)，命令及记录字段见[执行与发布](publishing.md)。

| 机制 | 如何采用 |
| --- | --- |
| 原创数量空间 | 主帖和逐串回复的额度允许少用；冷场和未接完的串可以保留。 |
| 原创表达机会 | 动机、篇幅、姿态、媒体组合从实际话头采用；抽中的负面倾向保留，具体方向可调整。媒体机会在构思时认真展开，终稿稀少时回查实际取舍。 |
| 现实案例 | 本轮固定案例沿已读原素材的篇幅、媒体与互动形成，不套原创抽签。 |
| 全轮终稿要求 | 两路共同满足权限、事实、时间、父关系、媒体真实性、实际分类、负面底线和整轮审读。图片、表情与生活照片没有终稿数量配额。 |

## 本次更新

| 参数 | 抽取内容与用途 |
| --- | --- |
| `lottery.rootBudget` | 按 `bands` 的档位权重选取范围，再在范围内抽取本轮原创新主帖额度；旧配置的 `min`、`max` 形态按均匀整数抽取。 |
| `lottery.authors` | 从有发布权限的已有账号中，按人物活跃权重选取 `candidates` 位候选。`recentPosts` 指定近期观察窗口，`recentMultiplier` 调整近期已发言者的抽中机会。 |
| `replyLottery.bands` | 原创根串独立按档位权重抽取新增回复额度，再在该档的整数范围内抽取。范围包含零的档位可以形成冷场，较高档位提供偶发热帖的空间。 |
| `replyLottery.maxReplies` | 限制原创一路的本轮新增回复总量，案例改编沿实际采用的源帖与回复另计。 |
| `maxBatchPosts` | 所有待导入发言合计的硬上限，包含原创和案例。当前为120条，区别于原创抽取额度。 |
| `lottery.discussion.negativeProbability` | 原创本条获得负面倾向的概率，当前50%；采用方式见[负面与回复提示](#负面与回复提示)。 |
| `lottery.discussion.minimumNegativeShare` | v2按终稿核对本轮全部实际发言的负面底线，当前一半，奇数向上取整；包括原创与案例、主帖与回复。 |
| `lottery.participation.version` | 当前为2，人物通常时段作为宽松偏好，负面份量与具体表达分别处理；保存人物时段快照，见[身份、处境与可用时间](#身份处境与可用时间)。 |
| `lottery.sampling` | 为各类素材独立抽取列表起点 `offset` 与连续读取数量 `count`，在准备结果的 `researchWindows` 中返回。 |
| `lottery.diversity.recentUpdates` | 策划输入提供最近多少轮归档发言，供本轮内容、口吻与画面对照；审读方法见[写作与改编](writing.md#审读)，保存方式见[执行与发布](publishing.md#生成并归档配图)。 |

每轮表示一次日常发帖操作。原创主帖额度可以为零，仍可接续旧串，固定案例则照常形成；零原创额度不表示本轮可以省去案例。单纯研究或规则维护直接修改相应资料，不启动日常发帖操作。旧串确有可回应的具体内容时再接续，不要求每轮安排人物回归或跨帖串联。每条楼中楼计入所属根串，累计楼层随多轮更新增长。

原创主帖与回复的实际采用量按当次话头形成。抽中较大额度时，可以集中来回，也可以只采用一部分；多个串的额度合计超过整轮上限时，优先采用已有来回和本次有具体开口的发言，有后续材料的串在之后继续。冷下来的串沿当时状态保留。

用户指定总量时，`--count N` 接受 1–120 的整数，作为原创主帖与回复合计上限；案例改编不占原创额度，两路发言合计仍受 `maxBatchPosts` 约束。数量档位用于形成本站日常发言较密、部分串集中来回的节奏；现实样本与适用范围见[研究-评论与点赞](../environment/research-comments.md#热闹怎样积累)。

素材入口使用最新排序，从 `offset` 跳过的条目之后连续读取 `count` 条原帖，保留普通、低互动与重复话题。入口内容不足时继续翻页；页面访问受限时记录实际范围，再使用该专题的其他可读入口。

## 研究补充

准备时自动识别 `docs/`、`environment/`、`users/` 中以 `research-` 开头、以 `.md` 结尾的研究文档，新增文档随下一次新操作纳入候选。

| 参数 | 用途 |
| --- | --- |
| `lottery.researchMaintenance.probability` | 每轮开展研究补充的概率 |
| `lottery.researchMaintenance.maxDocuments` | 一轮最多选取的研究文档数 |
| `lottery.researchMaintenance.ageWeightDays` | 每经过多少天，为文档增加一档抽中权重 |
| `lottery.researchMaintenance.maxAgeWeight` | 文档抽中权重的上限 |

先抽取本轮是否开展，再按权重选取文档。以最近一次文件提交的时间计算距本次准备时刻的天数，权重为 `min(maxAgeWeight, 1 + floor(天数 / ageWeightDays))`；尚无提交记录的文档采用最高权重。多份文档采用不放回抽取。

`plan.researchMaintenance` 保存候选路径、提交日期与抽中路径；同一操作恢复时沿用这份结果。已有操作继续原任务，后续新操作采用新增配置。实际阅读、补充与结果记录见[研究补充步骤](publishing.md#研究补充)。

## 每条发言

原创 `brief` 根据帖号取得可复现的机会提示，返回单人写作材料和策划信息。案例材料按[改编流程](publishing.md#逐条写作)读取源帖及其已采用互动，不使用本节的内容抽签。

| 参数 | 用途 |
| --- | --- |
| `authorKind` | 在无登记档案的 `guest` 与有档案的 `library` 之间抽取可用身份，只区分资料来源，不表示与其他人是否认识；已有草稿沿用原作者。 |
| `motivation` | 抽取求助、烦躁、随口想法、分享、纠正或高兴等普通开口动机。普通动机、篇幅与回复姿态帮助进入话头，不是逐项完成的清单。 |
| `discussion.negativeMotivation` | 抽中负面候选时，独立选取抱怨、八卦、争议立场、利益冲突或猜疑；具体表现可以调整，抽中负面时保留其倾向，不要求有合理委屈或完整争端。 |
| `discussion.replyAuthor` | 回复独立抽取本串新来者（`new`）、原作者（`root`）或已有参与者（`participant`），这些值只指本串参与位置，不表示熟悉程度。原作者与参与者从截至本条时间已出现、仍可回复的身份中选取；参与者池排除原作者，可用身份不足时改用本串新来者。 |
| `discussion.replyStance` | 回复独立抽取支持、顶回去、质疑、护短、起哄、追问或岔开话题等参与候选，结合实际可见话头和本人的开口理由采用。 |
| `length` | 抽取片语、短段或展开讲述的篇幅倾向；片语可以只有一句或几个词，具体句子按人物表达资料形成。 |
| `conditionCount` | 决定本次交给写作者的动机、篇幅提示数量。采用方式结合这位人物的当下处境，事实核对沿正式资料进行。 |
| `waitSeconds` | 抽取发言间隔，提供时间线节奏。启用 `participation` 时，在身份、父帖和本人先前发言确定后，结合保存的人物偏好与父帖安排时间，允许偶发时段外发言；旧操作沿原规则恢复。该间隔不要求执行者实际等待，见[发布流程](publishing.md#逐条写作)。 |
| `reading`、`nearbyReplies` | 决定回复者读到目标帖、根帖加目标帖，或目标附近的部分发言。 |
| `textWindow`、`excerptCharacters` | 决定读到完整正文、开头或局部片段，以及截取长度。输出保留来源帖号，并标明截取状态。 |
| `media.profiles` | 先抽整轮媒体倾向，再按主帖、回复各自权重，为每条发言抽取一种媒体组合，见[图片与表情抽取](#图片与表情抽取)。 |
| `media.images.root.types`、`media.images.reply.types` | 组合含普通图时，为主帖、回复提供媒介类型建议。 |
| `media.emotes.root.counts`、`media.emotes.reply.counts` | 组合含表情时，为主帖、回复提供表情张数建议。 |
| `likes.root`、`likes.reply` | 分别给主帖和回复抽取基础赞数建议，按权重选档后取该档内整数；结合[研究-评论与点赞](../environment/research-comments.md#点赞怎样形成差异)审定。 |

### 身份、处境与可用时间

新操作保存 `lottery.participation: { "version": 2 }`，`prepare` 从全部账号登记的结构化 `postingWindows` 与 `timezone` 取得 `plan.participationSchedules` 快照。所有人物使用同一套规则，各人的资料只提供不同偏好。中文 `activeHours` 供阅读，未明确到钟点的习惯保持开放，不从“饭后”推定一段必须遵守的精确时间。

常用时段是概率偏好。窗口内有常用时段时，约85%的机会优先采用，另有机会在其余时间出现；窗口内已没有常用时段、或身份未登记明确窗口时，仍可在合法范围内发言。普通时段外发言无须解释或登记理由，时间本身影响话头时才采用已知的具体情境。工具不会为时间自动编造失眠、轮班等经历。

独立主帖在本轮保存窗口与既有归档时间线之后的交集中分散排时；各条不接在本轮上一条草稿后面。回复以真实父帖、本人此前发言和抽中的间隔为参照，合法且合适时保留来回节奏，越界则在可用范围内稳定抽取，不统一压到当前时刻。回复不早于父帖与本人此前发言，不超过真实当前时刻及保存窗口结束；已保存草稿沿原时间恢复。没有合法时间时 `writer: null`，跳过或后续接续。

确需指定本次时间时，`operation.timingExceptions[postId]` 可填写 `createdAt`，`reason` 仅在有已知情境时填写。旧操作的区别集中见[保存与恢复](#保存与恢复)。

v2不要求为每条原创证明开口理由，`reviews.context` 只在核对事实、知情或需要说明的改写时选填；填入时继续验证引用范围与终稿摘要。最低限度的负面分类与整轮审读见[填写当前更新](publishing.md#填写当前更新)。

### 图片与表情抽取

原创媒体参数集中在 [publication.json](../publication.json) 的 `lottery.media` 中。先按本轮种子与权重从 `profiles` 选取一个整体倾向，再按该档对主帖、回复的不同权重逐帖抽取。每条只抽一次组合，结果为 `none`（纯文字）、`image`（普通图）、`emote`（表情）或 `both`（普通图与表情）。不同更新可以偏重生活图片、混合交流或文字聊天，同一轮也允许若干串集中出现图片或表情。

| 参数 | 含义 |
| --- | --- |
| `media.profiles[].id`、`weight` | 整轮媒体倾向的标识与抽中权重；同一操作沿用同一档。 |
| `media.profiles[].root`、`reply` | 主帖、回复各自的四种组合权重，组合内不再独立抽两次图片与表情机会。 |
| `media.images.root.types`、`media.images.reply.types` | 组合含普通图时，按权重建议 `photo`、`screenshot` 或 `illustration`，供构思照片、截图、作品图或示意字图。 |
| `media.emotes.root.counts`、`media.emotes.reply.counts` | 组合含表情时，按档位权重建议本条张数；不含表情时为零。 |

原创 `brief` 的 `writer.presentation` 给出组合、整轮倾向、普通图片类型和表情张数建议。先把媒体当作这次表达的一部分构思，再决定具体画面；不要先把所有发言写成纯文字，最后把图当可省略的装饰。人物的用图习惯从本人档案和既往发言理解，不额外抽取固定的性格标签。建议与具体话头不合时可以调整，也可在更合适的原创发言中形成对应的发图机会；案例仍沿原互动，不为原创差额改动源结构。

`suggest.mediaFollowThrough` 分别对普通图与表情给出 `suggestedPosts`、`actualPosts`、`shortfall` 及主帖、回复分项，`reviewRequired` 提示是否需要回查。它比较抽到的机会与实际采用，不是完成量下限。终稿明显少图或少表情时，回看具体候选是否尚未取得素材、被编辑惯性删除、误把熟图复用当重复，或确实不合这次表达；在整轮审读中写清相关帖号及取舍。不能为消除提示机械补图，也不能用一句“建议可覆盖”略过实际机会。照片丰富度、画面差异与表情用法按[配图](writing.md#配图)审读。

每张实际普通图片仍按[配图归档](publishing.md#生成并归档配图)记录 `mediaReviews`，区分生活照片、其他照片、截图与绘图。来源和复用如实登记；普通图与表情按各自用途分类，引用同一个熟图不需要换文件名制造差异。调整终稿不改原抽签、帖号、作者和时间，重复取得材料也不重抽建议。

### 负面与回复提示

当前原创负面倾向的抽中概率为50%，本轮终稿全部实际发言另以一半为底线核对，奇数向上取整。两者分别管生成机会与实际采用量，不是网络人群的统计结论，也不是每个人固定一半时间都在骂人。负面可以集中在一段争执，也可以散在许多互不相关的嫌弃中，不按正负交替排帖，不在每个串、每个人名下逐一凑比例。逐条 `brief` 不催补前缀差额，稿件形成后在 `suggest.discussion` 查看实际分类与整批底线。

`writer.discussion.candidates` 保留抽中的负面方向与回复姿态。负面倾向保留，具体方向随眼前话头调整；嫌烦、酸一句或没有说清的骂声就可以完成表达，不必扩成有证据、有受害者和有反击的事件。回复姿态可以适配，不为抽到“顶回去”强造一个对手。普通动机与负面可以同时存在，例如一边问办法一边嫌东西烂。研究与判定见[研究-负面与争议](../environment/research-negative.md)。

| 提示值 | 发言方向 |
| --- | --- |
| `complaint`、`irritation` | 不满、嫌烦、重复念叨；可以没有完整经过 |
| `gossip`、`suspicion` | 听来一句、乱猜、怀疑；人物可以猜错，正式事实另核 |
| `dispute`、`grievance` | 不同意、想占理、觉得吃亏；不保证公允或讲清楚 |
| `contempt`、`envy` | 看不起、眼红、酸一句；不必坦白自己的动机 |
| `pile-on`、`grudge` | 跟着踩、抓住旧印象不放；解释出现后也可能懒得改口 |
| `support`、`ask-detail` | 认同一点、问一句、报相似情况；不承担推进全串的任务 |
| `push-back`、`doubt`、`defend`、`provoke` | 顶回去、质疑、护短、起哄，允许无理或没人理 |
| `dismiss`、`repeat`、`sidetrack` | 敷衍打发、重复、转去讲自己关心的事 |

候选独立于 `conditionCount`，随操作和帖号保持稳定；同一提示不规定句式、长度或故事走向。各条分别形成，整体允许几个人各说各话、局部复读、长话和短话并存、问了没答以及突然结束。整轮负面不足时，先检查取材与采用范围，保留有负面倾向的普通发言；案例内容仍沿源帖，不把中性案例硬改成冲突。固定案例均中性、又没有合适原创或旧串话头时，保留未发布材料与原计划；确需重新取材时在另一个仓库外工作目录准备新轮，不声称原轮已经完成，不为原轮硬加负面回复或重抽案例。恢复边界见[恢复与修正](publishing.md#恢复与修正)。

每条实际发言填写简短 `reviews` 分类，注明实际语气即可，不要求逐条写人物动机报告。`reviews.context` 可选，有需要时再记录事实与引用判断。

`writer` 包含本人的资料、当次写作条件和实际可见内容；`editor` 保存作者选择、等待与图片等策划信息。每条写好后保存进草稿，再获取下一位参与者的材料。已有账号按当前回复权限参与，写作材料随所选身份读取本人资料和既往发言。

当前新主帖抽到 `guest` 时生成新身份；临时路人的返回入口是原串的 `root` 或 `participant` 回复。需要接续其已经发生的事情时，沿这些入口取得本人材料，保留原编号、网名与公开背景。有档案的账号可按权限在不同串出现，是否认识他人仍按[写作中的知情边界](writing.md)处理。历史临时路人另开新主帖尚无自动抽取入口，本页不把它作为当前已支持的行为。

按根串获取新回复时，先抽身份，再选目标。返回者优先接别人回应本人、且本人尚未回应过的最近一条；其余情况按保存种子在根帖、既有分支入口和近期回复之间选择，根帖的机会不随串变长而消失。候选只含本条时间之前仍可见的他人发言，返回者还排除自己已经回应的目标。没有新目标时沿新来者抽取结果开口，新来者从本串尚未出现的身份中选择，库内身份不足时使用新路人。具体接话依据见[组织一串交流](../environment/research-comments.md#组织一串交流)；已有明确话头时用 `--reply-to` 指定真正父帖，不为随机目标扭转原素材。指定父帖和已有草稿继续保留其目标，身份与时间沿原记录。

`editor.replyAuthor` 记录抽中及实际采用的身份类型，`editor.replyTarget` 记录实际目标及选择方式。`writer.thread` 只提供根串编号和本人在串内的参与位置；`new`、`root`、`participant` 不携带熟人关系，正文范围仍按 `reading` 与 `textWindow` 给出。

权重决定候选提示长期出现的机会，实际采用还取决于人物、可见内容和当时处境。一轮可以集中出现相似动机，也可以大部分无人回应；不把抽中提示本身当作此人必然这样回应的理由。

## 保存与恢复

新操作保存种子、配置、抽中的候选与本次时间窗口；时间窗口为准备时刻之前的24小时。整轮媒体倾向、主帖、逐串回复和逐条提示使用各自稳定的抽取标识，同一操作及帖号重复执行时沿用结果。配置调整用于后续新操作，资料更新后重新准备会刷新阅读内容。

当前新操作采用 `participation.version: 2`：常用时段是偏好，负面机会与全轮终稿底线分别核对，处境审读按需填写。恢复时只刷新资料，不替换原抽签快照；当前账号权限、真实时间与事实变化照常核对。

### 旧操作兼容

| 保存的结构 | 恢复行为 |
| --- | --- |
| `participation.version: 1` | 沿原结构化时段排时，时段例外保留明确理由；每条原创保留强制 `reviews.context`。 |
| 没有 `participation` | 沿原排时与讨论提示：超出间隔压到当前时刻，负面命中时替代普通动机，保留原 `toneSuggestion`、`replyStance` 与审读字段。 |
| 没有 `discussion` 或 `replyAuthor` | 继续原操作，不补入新的讨论或身份抽取义务。 |
| 旧 `image` 或独立媒体池 | 沿保存的抽取及原有媒体下限；当前联合组合的宽松采用规则不回写旧操作。 |

处境审读使用以下结构；当前操作只有确需核对事实、知情或具体改写时才填写，旧v1按原要求填写：

```json
"context": {
  "decision": "adapt",
  "action": "询问桌腿接口是否松脱",
  "basis": [
    { "kind": "visible-post", "ref": "实际可见父帖ID", "detail": "父帖只展示了晃动位置，尚未说明接口情况。" }
  ],
  "postDigest": "复制 suggest 对应帖号的 postDigest"
}
```

`decision` 为 `use`、`adapt` 或 `drop`。`basis.kind` 可为 `situation`（`ref: null`，已明确的本次情境）、`profile`（本人档案路径）、`visible-post`（本条实际可见帖号）或 `own-post`（本人已有帖号）；`detail` 说明与本次动作的关系，不拿抽签或他人私下档案当依据。摘要从 `suggest.contextReviewBasis` 按 `postId` 复制；公开字段变化后重新审读并取得摘要。案例沿源互动，不强套原创处境记录。

例行配置更新不迁移已归档帖子。用户指定的历史修订沿[恢复与修正](publishing.md#恢复与修正)处理；不按新概率给旧帖重抽或补量。

实现集中在 `tools/lottery.js`；`tools/operations.js` 负责读取资料、保存操作与组织流程。当前工作文件和恢复命令见[执行与发布](publishing.md#恢复与修正)。
