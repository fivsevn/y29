# 抽签规则

每次更新先保存种子与配置快照，后续按操作编号、帖号和抽取项目重现结果。数值集中在 [publication.json](../publication.json)，本页说明参数含义和使用方式；命令见[执行与发布](publishing.md)。

## 本次更新

| 参数 | 抽取内容与用途 |
| --- | --- |
| `lottery.rootBudget` | 按 `bands` 的档位权重选取范围，再在范围内抽取本轮新主帖额度；旧配置的 `min`、`max` 形态按均匀整数抽取。 |
| `lottery.authors` | 从有发布权限的已有账号中，按人物活跃权重选取 `candidates` 位候选。`recentPosts` 指定近期观察窗口，`recentMultiplier` 调整近期已发言者的抽中机会。 |
| `replyLottery.bands` | 每个根串独立按档位权重抽取新增回复额度，再在该档的整数范围内抽取。范围包含零的档位可以形成冷场，较高档位提供偶发热帖的空间。 |
| `replyLottery.maxReplies`、`maxBatchPosts` | 分别限制一轮新增回复总量和全部发言总量。 |
| `lottery.discussion.minimumNegativeShare` | 实际采用发言的负面最低占比；计算与提示见[负面与回复提示](#负面与回复提示)。 |
| `lottery.sampling` | 为各类素材独立抽取列表起点 `offset` 与连续读取数量 `count`，在准备结果的 `researchWindows` 中返回。 |

每轮表示一次更新操作。主帖额度可以为零，这一轮仍可接续旧串、补充研究，或完成观察后结束。先从已有材料决定实际主帖，再从最新发言与明确后续中选择要接续的旧串，逐串抽取本轮新增回复额度。每条楼中楼计入所属根串；累计楼层随多轮更新增长。

主帖与回复的实际采用量按当次话头形成。抽中较大额度时，可以集中来回，也可以只采用一部分；多个串的额度合计超过整轮上限时，优先采用已有来回和本次有具体开口的发言，有后续材料的串在之后继续。冷下来的串沿当时状态保留。

用户指定总量时，`--count N` 接受 1–120 的整数，作为本次主帖与回复合计上限，同时受当前发布硬上限约束。数量档位用于形成本站日常发言较密、部分串集中来回的节奏；现实样本与适用范围见[评论与点赞研究](../environment/comments-research.md#热闹怎样积累)。

素材入口使用最新排序，从 `offset` 跳过的条目之后连续读取 `count` 条原帖，保留普通、低互动与重复话题。入口内容不足时继续翻页；页面访问受限时记录实际范围，再使用该专题的其他可读入口。

## 研究补充

准备时自动识别 `docs/`、`environment/`、`users/` 中以 `-research.md` 结尾的研究文档，新增文档随下一次新操作纳入候选。

| 参数 | 用途 |
| --- | --- |
| `lottery.researchMaintenance.probability` | 每轮开展研究补充的概率 |
| `lottery.researchMaintenance.maxDocuments` | 一轮最多选取的研究文档数 |
| `lottery.researchMaintenance.ageWeightDays` | 每经过多少天，为文档增加一档抽中权重 |
| `lottery.researchMaintenance.maxAgeWeight` | 文档抽中权重的上限 |

先抽取本轮是否开展，再按权重选取文档。以最近一次文件提交的时间计算距本次准备时刻的天数，权重为 `min(maxAgeWeight, 1 + floor(天数 / ageWeightDays))`；尚无提交记录的文档采用最高权重。多份文档采用不放回抽取。

`plan.researchMaintenance` 保存候选路径、提交日期与抽中路径；同一操作恢复时沿用这份结果。已有操作继续原任务，后续新操作采用新增配置。实际阅读、补充与结果记录见[研究补充步骤](publishing.md#研究补充)。

## 每条发言

`brief` 根据帖号抽取条件，返回单人写作材料和策划信息。

| 参数 | 用途 |
| --- | --- |
| `authorKind` | 新来者在临时路人与已有用户之间抽取类型，并选择有权限的作者；已有草稿沿用原身份。 |
| `motivation` | 主帖在自由条件下抽取求助、烦躁、随口想法、分享、纠正或高兴等开口动机。启用讨论配置的回复使用 `replyStance` 提供参与动作。 |
| `discussion.negativeMotivation` | 存在负面缺口时，独立抽取抱怨、八卦、争议立场、利益冲突或猜疑，替代普通动机；对应提示完整交给写作者。 |
| `discussion.replyAuthor` | 回复独立抽取新来者（`new`）、原作者（`root`）或已有参与者（`participant`）。原作者与参与者从本串截至本条时间已出现、仍可回复的身份中选取；参与者池排除原作者。可用身份不足时沿原新来者抽取结果形成回复。 |
| `discussion.replyStance` | 回复独立抽一次支持、顶回去、质疑、护短、起哄、追问或岔开话题的动作机会，结合实际可见话头采用；普通条件仅保留抽中的篇幅提示。 |
| `length` | 抽取片语、短段或展开讲述的篇幅倾向；具体句子按人物表达资料形成。 |
| `conditionCount` | 决定本次交给写作者的动机、篇幅提示数量。采用方式结合这位人物的当下处境，事实核对沿正式资料进行。 |
| `waitSeconds` | 抽取从相关发言到本次发言的等待时长，工具据此安排草稿时间，并按[发布流程](publishing.md#逐条写作)返回本轮可写或延后的状态。 |
| `reading`、`nearbyReplies` | 决定回复者读到目标帖、根帖加目标帖，或目标附近的部分发言。 |
| `textWindow`、`excerptCharacters` | 决定读到完整正文、开头或局部片段，以及截取长度。输出保留来源帖号，并标明截取状态。 |
| `image` | 按条抽取纯文字、现场照片、截图或表情图的表达机会。建议独立抽取，不保证满足整轮配图下限；策划按[配图](writing.md#配图)统筹实际采用量与用途。 |
| `likes.root`、`likes.reply` | 分别给主帖和回复抽取基础赞数建议，按权重选档后取该档内整数；结合[评论与点赞研究](../environment/comments-research.md#点赞怎样形成差异)审定。 |

### 负面与回复提示

`writer.discussion.requiredTone` 为 `negative` 时，把这条写成有具体不满、质疑、八卦判断或立场冲突的发言；为 `open` 时，按当事人此刻想说的内容形成发言。负面研究与取材见[负面与冲突](../environment/negative-research.md)，正文和图片由审读者核对后登记结果。

| 提示值 | 发言方向 |
| --- | --- |
| `complaint` | 把不满落到具体人的做法、安排、评价或带来的代价上 |
| `gossip` | 说出目击、听来的异常或反常关系，保留自己掌握的范围与仍在猜的部分 |
| `dispute` | 对一种做法或流行说法表明立场，让别人有可以反驳的具体判断 |
| `grievance` | 交代谁占便宜、谁付代价、边界怎样被踩到，以及自己想争什么 |
| `suspicion` | 抓住一个说不通的细节，提出猜测、追问或质疑 |
| `support` | 接住目标发言中自己认可的那一点，可以直接答复、确认、报告相似经历，或只留一句认同 |
| `push-back` | 对目标的一句判断直接顶回去 |
| `doubt` | 质疑信息、证据、说法或讲述者的偏向 |
| `defend` | 从自己的利益或经验替被批评的一方说话 |
| `provoke` | 围着眼前的话头起哄、反讽或故意再刺一句 |
| `ask-detail` | 询问自己没看清的条件、操作或后续；得到答复后可以接着问、接受补充或离开 |
| `sidetrack` | 把自己在意的另一件事带进当前话头 |

这些提示提供开口机会，采用时先看本人为什么要回、实际看见了哪一句。普通回答、顺口确认或没有新增信息的一句，也可以完成参与；抽到质疑、顶回去或起哄时，由眼前话头和本人的触发点决定回应哪处。交流的组织与停顿见[评论研究](../environment/comments-research.md#组织一串交流)，抬杠怎样引起回应、转移话题或无人理会，见[冲突研究](../environment/negative-research.md)。

下一条的缺口用已采用草稿与其审读记录计算。当前需要的负面数为 `ceil((已采用条数 + 1) × minimumNegativeShare)`；已有负面不足该数时，`requiredTone` 为 `negative`。这项提示独立于 `conditionCount`，普通动机提示在此时由负面动机替代。审读记录按实际内容填写，程序核对登记与算数，审读者判断语义。每轮末尾按最终实际条数再核对一次。

`writer` 包含本人的资料、当次写作条件和实际可见内容；`editor` 保存作者选择、等待与图片等策划信息。每条写好后保存进草稿，再获取下一位参与者的材料。已有账号按当前回复权限参与，写作材料随所选身份读取本人资料和既往发言。

当前新主帖抽到 `guest` 时生成新身份；临时路人的返回入口是原串的 `root` 或 `participant` 回复。需要接续其已经发生的事情时，沿这些入口取得本人材料，保留原编号、网名与公开背景。库内账号可以按权限在不同串出现；每轮不另设熟人出场数量。历史临时路人另开新主帖尚无自动抽取入口，本页不把它作为当前已支持的行为。

按根串获取新回复时，先抽取身份，再按实际发言关系选择目标。返回者优先接别人回应本人、且本人尚未回应过的最近一条，否则接本串尚未回应过的他人发言；已回应的目标按本人已有发言的 `replyTo` 判断。没有新目标时沿新来者抽取结果开口，新来者从本串尚未出现的身份中选择，库内身份不足时使用新路人。新来者接本串最近的他人发言。候选限于本条时间之前仍可见的内容，目标排除本人。指定父帖时保留该目标，返回身份从目标作者以外选取。已有草稿保留原作者、父帖和时间。

`editor.replyAuthor` 记录抽中及实际采用的身份类型，`editor.replyTarget` 记录实际目标及选择方式。`writer.thread` 只提供根串编号和本人在串内的身份，正文范围仍按 `reading` 与 `textWindow` 给出。

权重决定长期出现机会。一轮可以集中出现相似动机，也可以大部分无人回应。每人的说话习惯从本人档案读取，抽中的情境通过这个人的方式表达。

## 保存与恢复

新操作保存种子、配置、抽中的候选与本次时间窗口；时间窗口为准备时刻之前的24小时。主帖、逐串回复、逐条条件与配图建议使用各自独立的抽取标识，同一操作及帖号重复执行时沿用结果。配置调整用于后续新操作，已保存操作按原快照继续；资料更新后重新准备会刷新阅读内容。已有快照缺少 `discussion` 或 `replyAuthor` 的操作沿原结果完成，后续新操作使用新配置。

实现集中在 `tools/lottery.js`；`tools/operations.js` 负责读取资料、保存操作与组织流程。当前工作文件和恢复命令见[执行与发布](publishing.md#恢复与修正)。
