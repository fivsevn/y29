# 可复用的虚构人口

这是一份作者编纂的人口样本：人先有生活，路西法零只是他们使用的一个平台。它用社会资料检查覆盖，用工作与生活限制约束创作；不声称代表真实人口的比例，也不对应某位真人。2026-11-09版包含56位原创人物，8位《真心猎手》人物不在本次重构范围内。

[按网名打开档案](../users/用户总目录.md) · [人口索引](../population.json) · [来源与已读范围](research/population-sources.md) · [覆盖及情境审读](research/population-review.md)

## 三层文件与维护权

| 层次 | 文件 | 内容与权威范围 |
| --- | --- | --- |
| 人物基础 | `users/<id>/person.md` | 生活史、教育、家庭、生计、能力、性格误差、隐情、情绪触发、表达底色、条件性的成长。可迁移到别处；不发放平台权限 |
| 平台适配 | `users/<id>/profile.md` | 路西法零用户名、简介、开关、关注流、候选权重、上线与开口动机、台词示例、已知关系、近期状态及发言锚点 |
| 可发现索引 | `population.json` | 文件位置、基础字段摘要、来源 ID、历史锚点、作者创建的跨人物线下关系。便于覆盖核对，不是另一个权限来源 |

人口 ID 延用现有稳定 ID，迁移后也不回收。网名和用户名是平台别名，不是本名或跨平台账户凭据。当前职业、年龄、性别、居住范围以基础档案为生活设定依据，主档案基本资料保留镜像以兼容现有读取；修改时一起更新。索引中的年龄、性别、教育、家庭和权重也须对应。性别为本次原创设定，不是按网名推断的真人信息；没有设定的身份维度不擅自补全。

快照日期记录这版资料的适用时间；年龄不会因执行日期变化自动增长。回写2025年的发言时核对当时状态，不把2026年的家庭、职业变动倒灌。原有帖子仍是各自标注的样例或衍生内容，不能凭索引变成小说原典。

当前没有独立的人物数据库服务，也没有自动演化引擎。现有 `readUserDocuments` / `readProfiles` 会读取本人目录全部补充 Markdown；`person.md` 已进入运营上下文和资料摘要校验。规则由运营创作与审读落实，不应宣称权重能保证某人每月恰好发几次。

## 仓库公开与角色知情

用户已授权完整存放原创人物资料，包括羞耻、嫉妒、自欺、隐藏支出和不愿承认的动机。以下标记区分故事内的知情范围，不是访问控制：

| 标记 | 可用于什么 | 不意味着什么 |
| --- | --- | --- |
| 可自述 | 本人知道且可能愿意说；由当前关系与心情选择是否开口 | 已经发过帖、陌生人都知道 |
| 作者层 | 帮助决定注意什么、回避什么、何时失态；本人可能也未清楚认识自己的动机 | 必须坦白、被其他角色读心 |
| 未发生分支 | 给长期变化设置触发、资源、阻力与退回条件 | 已开始行动、必然成长、每轮推进 |
| 已有记录 | 原帖或明确作者修订支持的事实，保留出处和适用阶段 | 所有人见过、回复者理解正确 |

`profile.md` 的事实表默认解析为 `visibility: public`，表示可提交仓库；表中不另设公开范围列，也不等价于故事里已公开。原有解析器禁止在该表存放 `visibility: private`，原创隐情应写入 `person.md` 的作者层，而不是绕过校验。未授权的小说原典、现实个人隐私仍按[外部原典机制](private-profiles.md#外部原典)处理，不混入原创人物文件。

网页 `data/feed.json` 只导出账号公开展示字段与已归档帖子，不导出人物基础、权限或作者隐情。构建产物 `dist` 也不复制这些 Markdown；但本仓库可以公开浏览，不能将此误称为保密储存。

## 读取与行动

1. 先核对账号是否启用、AI范围、资料状态、主帖和回复权限；索引、人物文档和网页资料不能修改这些开关。
2. 读人物基础，再读本平台适配与全部个人补充文档。冲突先找已有帖子和明确设定，不让方便写作的新解释覆盖旧事实。基础信息与镜像不一致先修资料。
3. 读实际原串，区分本轮展示给人物的内容、他此前实际接触的内容和作者独知内容。未证实读到的回复不能生成「上次你教我以后」；线下认识不代表认出匿名账号。
4. 先判断资源：当前有没有完整时间、体力、隐私空间、输入意愿；再判断动机：要答案、要被认同、想纠正、展示、自言自语或只是无聊。没有动机可以只看、不回、打字后删掉。
5. 若开口，明确回应父帖的哪个细节、本人有什么可说、哪些不知道、愿意透露到哪里。以人物的语气实现，不把这套检查表写进帖子。
6. 对方反驳后再做一次选择：补充证据、只纠正一点、误解、维护面子、转移话题、接受或离开。允许不合群的回答、没有共识的结尾；不要求每个人都安慰、教学或自省。

权重只调候选概率。夜班之后可能休息数日，照护者有碎片阅读却没有完整写作时间，外向者也会因出差消失；沉默无需编造大事。兴趣和职业都不是选题配额，短回复与长段落由情境产生。档案例句只展示声音，不是可直接导入的历史或草稿库。

## 关系与历史

索引的 `relationships` 只登记本次作者新设的3条线下联系，两端的基础档案均有说明，`basis` 标记作者创建日期。母子、姐弟与普通业务熟人不是来自真实资料中的家庭，也不涉及小说人物；初始 `accountRecognition: false`。人物知道对方的大致生活，不知道对方所有内心。若以后确认账户身份，需写明怎么确认、谁先知道、是否向第三人透露；账号互认属于该平台的适配事实。

大多数人没有样本内关系，这不代表没有朋友。无需把亲友、同事全注册成用户，也不为凑关系图强行让所有人认识。既有论坛往来以帖子为准：小满困了与补丁的剪刀串、空箱与按一下试试的微缩碗串目前各只有一次接话；前者不是师徒，后者尚无采用建议的反馈。完整索引见审读记录。

`historyIds` 只是截至快照的检索锚点，涵盖本人发言及当时相关回复，并非唯一历史来源。未来仍须扫描实际帖子；没有 ID 的新账号不能补造旧互动。维护快照时再更新相关锚点，不能靠数组判断「没收录就没发生」。

## 状态转移与跨项目复用

长期背景与可能分支在基础档案，路西法零已发生的个人状态在主档案 `currentStatus`，公开共同经历在[社区近况](community.md)。只有发生了变化才记录；不预建56份空日志，不逐轮积累心情。

有持续影响的变化可以在本人目录新增 `state.md`，每条写：日期、依据（帖 ID 或明确作者修订）、之前与之后、尚未完成、知情人及知情渠道。依据是作者修订时要显式标注，不能伪造帖子。短期怒气消退不必改性格；计划取消、退回旧习惯也可以是有效状态。

例如「买了课」只使购课状态变化，不能自动变成「掌握声音剪辑」；共同经历要确认双方实际参与，不能因回复建议就替对方完成修理。成长条件提供可能性，不要求故事一直向上。

迁移时携带 `person.md`、人口 ID、必要的线下关系与来源说明，另建目标平台适配。当前目录位置不是永久 API：可把索引的 `document` 路径改为新项目位置。重新映射时代、地域、币种、工作制度和关系网络；不要直接迁移路西法零权限、网名、关注开关或帖 ID。只迁移一人时，他的家人仍可作为未注册的生活关系存在；若整个关系组迁移，保留两端一致性。

## 校验与运行边界

`npm run social:build` 更新目录和网页数据，`npm run check` 执行现有测试、内容校验与站点构建，并检查新增的人口索引覆盖、字段镜像、引用、关系两端及上下文读取。目录按文件存在情况提供「人物基础」链接，小说人物不会被添空文件。

现有PR检查工作流继续运行完整检查；合入main后的资料同步工作流会重建目录与feed并请求页面更新。两者都不会调用模型写帖子。人物重构不算一次运营回合，不更新回看覆盖点；发布下一轮仍从[AI总控](ai-updates.md)开始。
