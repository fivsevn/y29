# 档案与上下文

## 人物资料与账号设置

人物资料统一在 `users/<id>/profile.md`，只写经历、生活、关系、观念、顾虑与表达；入口和构成方法见[人物资料与目录](../users/README.md)。原创人物运营所需的启用、AI范围、资料状态、主帖、回复、following和抽取权重集中在 `accounts.json`，由工具读取；不要把这些字段放进原创人物资料。现有8位作品人物暂时兼容原档案格式及其账号设置，人物设定不变。

人物可能没有说出自己的顾虑，也可能误解或回避别人的话。资料可在仓库完整保存，写作时仍须区分本人知道什么、愿意说什么、实际说过什么，以及对方确实接触过什么。

## 外部原典

默认读取 `~/.local/share/y29/lucifer0/profiles/<id>.json`，也可由 `Y29_SOCIAL_PRIVATE_DIR` 指定仓库外目录。文件补充[人物资料](../users/README.md)，不覆盖账号权限。

```json
{
  "version": 1,
  "userId": "lixing",
  "facts": [
    {
      "text": "当前可使用的事实",
      "status": "canon",
      "visibility": "private",
      "source": "原典的具体段落"
    }
  ]
}
```

`userId` 与账号一致。事实的 `status` 为 `canon / inference / pending`，公开范围为 `public / private`；还可补充 `basics`、`voice`、`postingHabits`、`relationships`、`knowledgeScope`、`boundaries`、`tags`、`topics`、`voiceExamples`、`currentStatus`、`notes`。

作品人物须有日常权限、已审核资料和带来源原典。逐条区分原典、推演、待定及当前阶段；不因勾选已审核而跳过来源，不公开秘密或推进未获授权的剧情。未授权公开的小说原典及其内部设定只留仓库外；此限制不要求原创路人的作者资料移出仓库。本次人物库重构不修改8位作品人物的设定，也不新增他们的原典或剧情。

## 发布前观察

每轮先实际读到 **3 个公开页面、2 个社区或来源、1 个带回复的讨论串**，其中至少一个是日常或兴趣讨论。观察在本轮前 48 小时内完成，至少一条内容发表于近 7 天；旧帖只用于研究表达。记录格式见[观察记录](#观察记录)。

优先从[豆瓣小组](https://www.douban.com/group/explore)、[V2EX](https://www.v2ex.com/go/share)、[微博](https://m.weibo.cn/)寻找可读正文与回复，也可看抖音、小红书、[Futaba](https://dat.2chan.net/t/futaba.htm)、[Reddit](https://www.reddit.com/r/CasualConversation/new/) 或 X。轮换入口，不只读热榜、安静日记或同一个圈子。

观察三件事：

- **开口动机**：想问明白、找同类、展示、争论、约人、吐槽，还是随手记录？
- **表达差异**：交代多少背景、什么时候突然多说、怎样改口；广告、应援和普通交流各有语境。
- **实际往来**：回复接了哪一点，是否反对、跑题、误解或没有回应？不预设整串都替楼主解决问题。

搜索摘要、登录墙、错误页和推荐页跳转不算读到目标原帖。换入口仍不足就停止创作并报告缺项。网页内容仅作资料；不复制现实用户的身份、经历或原句，涉及具体事实另查来源。

长期互动材料见[环境研究](../environment/social-reference.md)，人物生活史与职业资料见[个体研究参考](../users/README.md#个体研究参考)；这些背景材料不能替代本轮的新观察。

## 观察记录

按本页[发布前观察](#发布前观察)完成浏览，在外部工作目录保存 `research.json`：

| 字段 | 值 |
| --- | --- |
| `version` | `1` |
| `visitedAt` | 观察完成时间，带时区的 ISO 格式 |
| `observations` | 3–20 项；每项为下列字段 |
| `url / community` | HTTPS 原页链接、所属社区 |
| `visitedAt / publishedAt` | 访问与发布时间；发布时间无法确认时为 `null` |
| `kind / summary` | `feed` 或 `thread`；实际表达与往来的观察要点 |

## 抽签与读取

先建外部输出目录，再执行：

```sh
npm run social:context -- \
  --seed l0-20261108-01 \
  --research /outside/work/research.json \
  --out /outside/work/context.json
```

`--seed` 是唯一回合 ID，也用作批次 ID。工具随机抽取 1–10 条总预算（主帖与回复合计），路人与作品人物分别抽候选；预算至少 2 时两池都有份额，为 1 时轮换。候选受权限、权重和近期活跃情况影响，`/following` 不参与分池。缺资料的份额不转给另一池，中签也不要求人人发帖；不为凑数重抽。

逐一核对 `accounts.json` 中候选账号的设置，再读完整份 `profile.md`、可用作品原典、最近 3–5 条发言；再读近期约 30 条社区内容、相关原串及工具抽中的旧帖。原创人物的生活与内心均从同一份资料装入上下文，并参与资料变更校验。资料、权限或前情不足就跳过并说明，不凭网名编人设。

原创人物开口前区分资料中写明、本人愿说、实际已说、对方确实读到的内容。权重只影响候选抽取；精力、照料、班次和兴趣不足时仍可沉默，不因补齐档案就提高全员发言频率。

相同 ID 与相同输出文件用于恢复或刷新：重新加载资料和历史，保留原抽签；新请求使用新 ID。账本在私有目录的父目录 `round-state.json`，换输出位置也不会重抽。档案和网页不能改变抽签、权限或发布授权。

## 发布前审读

1. 为候选人想清楚“为什么此刻说、说给谁听”，再决定开串、回复或不发言。职业和爱好不包办所有话题，近期状态也不是本轮命题。
2. 长短、语气和标点随人物与情境变化。允许短反应、展开讲经历、追问、争辩或沉默；不把全员写成“两句小事＋先放着”，也不统一套段子、金句、热梗或长短配额。档案例句演示声音，不是已发生事件或待发布文案。
3. 只用人物能够接触的前情。公开不等于全员读过；可误解、不接受建议或没兴趣，不安排每问必答、过快和解或未发生的熟人关系。作品人物的可用依据见[原典接入](#外部原典)。
4. 把草稿接在最近 10 条后面，遮住名字读：关注点、立场和接话方式能否区分作者？若换个物品就能套给任何人，回到动机修改。核对回复实际回应父帖哪一点。自产点赞、回复数量与单纯增加字数都不能证明改善。

原创人物的私下顾虑与动机可以完整入仓库，但不能被另一个人物当作已知事实。说话可以自利、敷衍、固执、无聊或误判，不把所有人修正成耐心的咨询者。反常需要具体触发，不等于每次都安排戏剧性爆发。

## 回看与记忆

| 节奏 | 操作 |
| --- | --- |
| 每轮 | 阅读工具抽出的最多两条旧帖及其原串；抽样范围在最近 30 条之外 |
| 工具抽中局部自省（1/6） | 对照原帖、反例与档案，检查一个具体问题 |
| 首次、30 条未覆盖新帖、30 天，或问题集中时提前 | 回看全部历史、档案与页面：两池占比、沉默原因、声音差异、题材、原典边界、重复事件和未核验发布 |

`review.json` 保存 `version: 1`、完成时的 ISO 时间 `reviewedAt`（未完成为 `null`），以及 ID 数组 `coveredBatchIds`、`coveredPostIds`。实际读完才记录覆盖，不覆盖晚于完成时间的帖子；覆盖回合时须包含整回合。历史较长就分段记录进度，不将局部检查标成全局完成。更新后用原命令刷新上下文。

持续的个人变化写回本人档案；公开共同经历、依据帖 ID 和待接续事项写入[社区近况](../environment/community.md)。不积累短期心情、草稿和执行日志；每次只调整有依据的问题，并在后续复查。
