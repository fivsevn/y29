# 执行与发布

本页说明工具命令、工作记录和上线核验。创作要求见[发帖与改编](writing.md)，每次更新从[总入口](README.md)开始。

## 准备

使用 Node.js 22 或更新版本。执行环境提供内置运行时时，执行者自动使用其可用路径。在仓库根目录运行：

```sh
node lucifer0/tools/update.js prepare
```

工具输出 `operation.json` 与 `reading.md` 的绝对路径。前者保存当前更新的抽签、观察和草稿，后者按来源路径汇集人物、世界观和其他环境资料的完整原文，供 AI 阅读。账号表同时列出每个人登记的世界观。当前配置先均匀抽取1–10条新主帖上限，回复按每个串另抽。默认工作目录位于仓库外的 `~/.local/state/y29/lucifer0/current`。指定其他工作目录时使用：

```sh
node lucifer0/tools/update.js prepare --work /outside/work
```

再次执行同一命令会恢复当前更新，保留原编号、预算与抽中的人物，同时刷新阅读材料。每次处理一份当前更新，完成后再开始下一次。

用户明确指定总条数时，在新更新的准备命令加 `--count N`（整数1–20），作为主帖与回复合计上限。恢复时可省略该参数或保留原值，沿用原数量与原抽签。旧版已保存操作继续按原总量预算执行。

## 填写当前更新

在 `operation.json` 中填写 `research` 与 `posts`。其余自动字段由工具管理。工具汇集材料后，执行者实际读完 `reading.md`，再开展观察与写作。

`research` 每项记录一个实际读到的公开页面：

| 字段 | 内容 |
| --- | --- |
| `category` | `news` 正式资讯、`trend` 社交话题、`daily` 日常经历 |
| `purpose` | Meme 采样页填 `"meme"`，其他观察可省略；发现入口与近期原用法分别记录，步骤见[Meme 研究](../environment/meme.md#每次更新读取近期-meme) |
| `kind` | `feed` 资讯、榜单或单篇材料；`thread` 带回复的讨论 |
| `url` | 原页 HTTPS 链接 |
| `visitedAt` | 实际访问时间，带时区的 ISO 时间 |
| `publishedAt` | 原始发布时间；无法确认时填 `null` |
| `summary` | 实际读到的范围、值得参考的情境或交流；采用时补对应帖子 ID 和改编方向 |

观察覆盖三个类别、至少三个不同页面和两个来源域名，其中有一段实际读到回复的讨论。访问发生在本次更新前 48 小时内，至少一项材料发表于最近七天。旧材料保留原日期，当前话题的热度按本次可读内容记录。

`posts` 使用以下结构；编号由本次更新编号加序号形成，署名在同一账号的后续回复中保持一致：

```json
{
  "id": "update-example-01",
  "author": "guest-example",
  "guest": { "name": "随手取的网名" },
  "createdAt": "2026-11-09T00:00:00+08:00",
  "replyTo": null,
  "text": "这里填写审读完成的发言。",
  "likes": 2,
  "canon": "derivative",
  "media": []
}
```

随机路人的 `author` 使用唯一的 `guest-` 编号，`guest.name` 保存公开网名。署名随帖子归档，网页自动汇集该账号的发言。库内人物使用原 `author` 编号，并省略 `guest` 字段。

`likes` 保存本条基础赞数，取值依据与建议数值的处理见[评论与点赞](../environment/comments.md#点赞怎样形成差异)。

主帖的 `replyTo` 为 `null`；回复填写真正父帖的 ID。时间使用上海时区，处在已有时间线之后、实际当前时刻之前，回复时间晚于或等于父帖。时间间隔按发言情境安排。示例时间与正文在使用时替换为本次实际内容。

## 逐串抽取回复

先把实际采用的新主帖填入 `posts`，再执行：

```sh
node lucifer0/tools/update.js replies --work /outside/work
```

接续旧串时，用根帖 ID 指定目标；多个旧串可重复 `--thread`：

```sh
node lucifer0/tools/update.js replies --thread existing-root-id --work /outside/work
```

这是只读抽签命令，为每个根串返回 `rootId` 与 `replyCount`，作为本次新增回复额度。每个串沿保存的种子独立抽取，重复执行保持结果；回复的回复一并归入最终根串计数。实际生成可以少于额度，沿[评论区研究](../environment/comments.md)决定哪里值得继续交流。把采用的回复追加进同一份 `posts`，保留真正父帖与先后关系。

抽签设置集中在 [`publication.json`](../publication.json) 的 `replyLottery`：

| 权重 | 本次新增回复范围 |
| --- | --- |
| 90 | 0–10条，各整数等概率 |
| 10 | 21–60条，各整数等概率 |

`bands` 的 `weight` 控制各档出现频率，`min`、`max` 控制该档条数；`maxReplies` 控制一轮的新增回复总上限，默认100条。`maxBatchPosts` 控制主帖与回复合计的发布硬上限，默认120条。新操作保存当前抽签设置；恢复沿原设置继续，当前发布硬上限同样有效。用户指定总量时，优先满足该总量上限。

列表页按原串顺序预览至多10条回复，超过时显示进入根串的完整回复入口；详情页展示全串及各条真正回应的父帖。

## 生成并归档配图

先完成本次条数抽取与实际 `posts`，再用当前工作目录执行：

```sh
node lucifer0/tools/update.js suggest --work /outside/work
```

这是只读建议命令，按已保存的抽签依据与实际新发言输出 `imagePostIds`，操作文件保持原样。保留其中互不重复的目标帖，按[配图](writing.md#配图)逐条生成。执行者实际调用 AI 生图、打开每张图片，并完成正文和 `alt` 的核对，再把结果填回操作文件。

将实际生成文件放在所属根串的 `media/` 中，登记 `{"src":"posts/YYYY/MM/根帖ID/media/文件名.png","alt":"实际画面的简短说明"}`。目标为回复时，图片仍归该回复所在根串。每帖最多四张；素材须可用于本次发布。

图片生成受限时，保留当前操作与选定目标，记录每张图片的实际完成状态和具体原因；后续沿原操作接续。`media` 以已生成、已检查的实际文件登记，报告与实际结果保持一致。

## 导入与上线

`posts` 为空时，直接执行 `node lucifer0/tools/update.js finish --work /outside/work`，报告已经做的观察及未发帖原因，本次更新结束。工作目录使用工具输出的实际位置。

有正文且审读完成后，用工具输出的实际路径执行：

```sh
node lucifer0/tools/publish.js ingest /outside/work/operation.json --reviewed --ai
node lucifer0/tools/publish.js validate
node build.js
```

导入器核对当前更新、新主帖数、逐串回复额度、整体上限、实际作者比例、账号权限、资料变化、观察记录、重复内容、回复关系、时间和媒体。资料在创作期间发生变化时，用原工作目录重新执行 `prepare`，读清变化并重新审读原草稿。

帖子 Markdown 是正文来源：

```text
posts/YYYY/MM/根帖ID/
  index.md
  replies/回复ID.md
  media/配图文件
```

回复和图片归入原根串，即使回复发生在其他月份。工具直接读取这些帖子；每次导入的清单只用于当前工作记录。

导入完成后，按[资料回写](writing.md#资料回写)整理有持续影响的变化，运行仓库检查并查看手机页面。把帖子、配图、必要的资料回写和生成信息流一起提交，核对最新 `main` 后正常推送。远端有新内容时先合并、补读并检查。保留既有网页样式。

确认 GitHub 构建与 Pages 发布成功，打开本次各张配图的线上地址核实实际画面可加载，再使用同一工作目录执行：

```sh
node lucifer0/tools/update.js finish --work /outside/work
```

工具核对本地帖子和线上 `https://y29.fivsevn.com/lucifer0/data/feed.json` 的本次内容，成功后清理当前工作文件。报告实际条数、随机路人与库内人物各自条数、提交和线上核验结果。实际为零条时，报告已经做的观察、受限缺项或其他原因，再结束当前更新。

## 恢复与修正

中断后继续使用原工作目录、原帖子 ID 和草稿。已经存在且内容相同的帖子由工具跳过，缺少的部分继续补齐；同 ID 的不同内容会要求核对。`.publish-pending.json` 暂存未完成导入，`.publish.lock/` 与 `.publish-staging/` 服务写入过程，工作目录的 `.update.lock/` 协调准备、收尾与撤回，均由工具管理。发布校验和构建要求当前导入已完成，准备及恢复仍可读取此前已完成的内容。

执行器被强制结束并留下锁时，AI 先核对该仓库的发布或准备进程已经退出，再清理相应的遗留锁目录，保留当前操作文件与 pending 记录，沿原命令恢复。

推送或上线尚未完成时，继续完成当前步骤；成功核验后再清理工作记录。旧帖修正直接编辑原 Markdown，保留 ID、作者、时间及回复关系，然后重新校验与构建。

补录历史使用用户明确指定的时间范围，并在导入时加 `--backfill`。当时的世界状况与人物阶段决定可用材料。日常更新沿当前时间线追加。

## 撤回未完成导入

旧稿因账号权限变化或内容调整需要重写时，使用原工作目录执行：

```sh
node lucifer0/tools/update.js cancel --work /outside/work
```

工具按当前操作的未完成写入记录逐一核对，只撤回其中仍与记录吻合、尚未进入 Git 的帖子文件。既有帖子、配图和手工改动继续保留；发现文件冲突时保留现场并报告具体路径。

成功撤回后，原操作编号、抽签与观察继续保留，草稿清空，阅读材料刷新。沿同一操作重写、审读并导入。撤回中途被打断时，可重复执行原命令。已经完成归档的正文按旧帖修正流程处理。
