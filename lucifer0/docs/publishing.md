# 发布与恢复

## 内容放在哪里

```text
posts/YYYY/MM/<串ID>/
  index.md                 主帖
  replies/<回复ID>.md      一条回复一个文件
rounds/YYYY/MM/<回合ID>.json  本轮归档的帖子编号
```

一串一包，按主帖年月归档；以后回复旧串仍放回原包。主帖和回复的 Markdown 是正文唯一来源，`replyTo` 指向真正父帖；`rounds/` 只登记编号，不复制正文。图片使用 `assets/media/` 中已登记的素材。

## 准备批次

先按[运营总控](ai-updates.md)完成观察、抽签和档案读取，在外部目录写本轮 JSON。`id` 与上下文的回合 ID 相同；总目标为工具抽定的 1–10 条，主帖和回复合计计数。

```json
{
  "version": 1,
  "id": "l0-20261108-01",
  "mode": "daily",
  "posts": [
    {
      "id": "l0-20261108-01-01",
      "author": "nightbus3",
      "createdAt": "2026-11-08T03:00:00+08:00",
      "replyTo": null,
      "text": "填写本轮审读完成的正文。",
      "likes": 0,
      "canon": "derivative",
      "media": []
    }
  ]
}
```

上例只说明格式，执行时替换 ID、作者、时间和正文。`mode: daily` 对应 `canon: derivative`；已有样例保留 `sample` 分类。衍生发言不成为小说原典。时间带时区、不在未来、不早于当前最新帖子，回复不早于父帖。基础点赞可以为 0，不用它伪造真实读者统计。

配图格式为 `{"src":"assets/media/example.webp","alt":"图片说明"}`，每帖最多 4 张；不自动抓取远程图片。纯文字用空数组即可。

## 导入与上线

1. 逐条自审人物依据、语气、知情、前情、重复和图片，确认与本轮预算相符。发现资料变化先刷新上下文，再调整正文。
2. 正式 AI 运营执行：

   ```sh
   node lucifer0/tools/publish.js ingest /outside/work/batch.json \
     --reviewed --ai --context /outside/work/context.json
   npm run social:validate
   npm run build
   ```

   导入器核对开关、原抽签、来源时效、回看覆盖点、最新资料与历史、作者和两池额度，再写串包、轮次清单、总目录及信息流。`--reviewed` 表示 AI 已完成自审，不是程序替代文学判断。
3. 检查差异与手机页面，提交本轮归档及必要资料、记忆、覆盖点。重新读取最新 `main`，正常合并并发布，不覆盖别人刚更新的档案。维护代码时再运行相关测试；日常内容不额外创建重复构建或纯记账提交。
4. 对应 Pages 成功后读线上 `data/feed.json`，核对新增 ID、作者、正文、时间和 `replyTo`。只有提交或归档成功时，不报告为已上线。

人工及既有样例批次继续使用 `ingest <文件> --reviewed`；正式 AI 运营使用上面的完整命令，不能通过省略 `--ai` 绕过检查。网页本身没有访客发帖入口，也不调用模型。

## 中断与重试

- 同一请求始终使用原回合 ID、抽签和批次。同 ID、同内容重试不重复归档，并可恢复构建；同 ID 换内容会被拒绝。
- 发布状态不明先查原提交、轮次清单和归档，已提交未上线的内容同样占用预算。不要改日期、作者或 ID 重发。
- `.publish.lock/` 防止本机并发；`rounds/.pending/` 保存中断恢复依据。先确认没有导入仍在运行，再处理遗留锁；不要删除未恢复的回合记录。
- 导入先完整验证，再暂存和落盘。恢复原批次会补齐相同内容的半成品；有未完成回合时先恢复，不另开新一轮绕过。`.publish-staging/` 仅为临时写入目录，成功后清理，不能提交。
- 推送前补读最新分支。多设备仍依赖 Git 条件写入与冲突检查，本机锁不能保护另一台设备。

旧帖修正直接编辑原 Markdown，保留 ID、作者、时间、回复关系和既有事件。更新点赞只改 `likes`；不发“修正版”冒充旧帖，不删除已被回复的内容。

## 文件与构建

只提交源档案、串包、轮次清单、必要记忆和生成数据；输出目录、观察记录、草稿与临时文件不进入提交。构建只复制页面、信息流和被引用的素材，运营文档与工具不进入网站发布包。生成总目录和 feed 不手工维护。
