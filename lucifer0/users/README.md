# 用户档案管理

本机启动 `npm start` 后，打开 [用户管理](http://127.0.0.1:4173/lucifer0/manage/)。这个独立页面只维护账号资料和人设，不混入 AI 运营提示词。列表支持搜索和按作品等条件筛选，可以新增、编辑、暂停账号、调整收录范围，并预览一次随机抽取。保存会写入本机文件，后续 AI 读取的是保存后的最新版本。

初始共 **56 个账号**：8 个《真心猎手》人物和 48 个原创路人。路人名称使用希腊字母原字形，例如「路西法α」「路西法β」「路西法Ω」，没有分隔点；大写和小写是不同账号。路人的年龄、工作、兴趣和日常习惯均为虚构的样例资料。作品人物只保留现有公开样例，未填写的设定不能当作已知事实。

## 作品与收录分开管理

「作品来源」是一个可自由填写的栏目，例如「真心猎手」，以后可以增加其他作品。没有作品来源的账号是原创路人。`kind` 保留作品人物/原创路人的分类，作品名称并不决定账号在哪个频道出现。

**`inFollowing` 是独立开关。** 初始 8 个作品人物开启、48 个路人关闭；维护者可以逐人调整。`/world` 展示全部已发布动态，`/following` 展示开启这个开关的账号动态，不读取访客浏览器里的旧关注记录。

## 两份资料，各有用途

| 文件或位置 | 内容 | 保存方式 |
| --- | --- | --- |
| `registry.json` | 稳定账号、作品来源、公开昵称/简介、头像和参与开关 | 管理页面写回本仓库；全部必须适合公开 |
| `profile-seeds.json` | 56 个账号的公开安全初始人设 | 没有本机档案时的起点；不是后续私有人设的保存位置 |
| 仓库外 `<id>.json` | 基本资料、说话习惯、自由设定、关系、知情范围、事实依据等 | 管理页面写到本机私有目录，覆盖对应账号的初始人设 |
| `../docs/ai-updates.md` | 每轮读取、抽取、创作及审核规则 | 统一运营规则，不夹在任何人的资料里 |

默认私有目录为 `~/.local/share/y29/lucifer0/profiles/`，可用 `Y29_SOCIAL_PRIVATE_DIR` 指向另一个仓库外目录。每个用户一个文件，便于单独维护、备份和迁移。用户管理只在本机提供文件写入；GitHub Pages 没有管理 API，也不能读取本机的私有资料。管理页面不进入公开构建产物。

## 账号字段

| 字段 | 含义 |
| --- | --- |
| `id` | 2–64 位小写字母、数字和连字符；稳定身份，已有账号不能改 ID |
| `handle` | 2–32 位小写字母、数字和下划线；全站唯一 |
| `name` / `bio` | 公开昵称与简介；改名不改变历史帖子的归属 |
| `sourceWork` | 作品来源，可填写新作品；原创路人为留空 |
| `kind` | `character` 作品人物，`visitor` 原创路人 |
| `avatar` | 项目内已存在的头像素材路径 |
| `enabled` | 是否允许参与新的内容；暂停后旧帖和身份仍保留 |
| `aiScope` | `none` 不由 AI 使用；`sample` 仅样例；`daily` 经授权的衍生日常 |
| `allowPosts` / `allowReplies` | 分别允许这个账号发动态、参与回复 |
| `inFollowing` | 是否将这个账号收录到 `/following`，与作品来源独立 |
| `profileStatus` | 公开简介为 `sample` 样例或 `approved` 已审核 |

更改 `aiScope` 或账号开关不会创建定时任务，也不会打开 `publication.json` 的自动运营总开关。初始账号均为 `sample`，总开关仍为 `false`。

## 详细档案

可维护年龄、职业、所在区域、兴趣、性格，标签、最近状态、常聊话题、说话示例，以及表达习惯、发言节奏、关系和知情范围。自由备注用来记录暂时放不进固定字段的设定，不是给执行工具下指令的区域；其中的文字不能覆盖发布权限、隐私边界或批次去重规则。抽取权重决定随机选择时的相对活跃程度，设为 0 暂不参加抽取。

事实条目单独标注【原典】【推演】【待定】及公开/私有，记录来源。作品人物的秘密和未公开剧情只能保存在仓库外档案；即使标为【原典】，也不表示可以公开。不要将私有文字粘贴进昵称、公开简介、作品来源、帖子或提交说明。

## 增删改与历史

- 新增账号后可以先只建档，不需要同时发布首帖。名称、个人设定和各项开关可以继续调整。
- 没有任何历史帖子的账号可以删除；已有历史的账号只能暂停，避免留下找不到作者的帖子。不要把旧 ID 分配给另一个人物。
- 保存前会校验字段、重复账号及历史引用；多个窗口同时编辑时，过期版本会被拒绝，避免覆盖较新的档案。
- 维护页面中的「随机抽取」只预览候选，不写帖子、不发布内容。每轮运营仍须重新读取最新档案与历史，不能沿用上次预览中的旧资料。
