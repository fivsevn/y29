# 用户档案

**[打开用户总目录](用户总目录.md)**

按网名找人：点网名进入个人文件夹，点「查看档案」阅读，点「编辑档案」直接打开 GitHub 编辑器。总目录由档案生成，不再维护第二张用户表。

## 每个人填什么

主档案是 `用户ID/profile.md`。它描述这个人在本平台上的账号与表现，不保存通用发帖提示词。原创路人另有 `person.md` 保存可迁移的人生、经济、关系、矛盾和成长条件；[人物库规则](../docs/population.md)说明两层怎样衔接，[人口索引](../population.json)列出文件、来源和历史锚点。

| 部分 | 填写内容 |
| --- | --- |
| 账号 | 稳定 ID、用户名、网名、简介、账号类型、作品来源；头像可留空，新增图片放本人文件夹 |
| 开关 | 启用、AI 范围、资料状态、主帖、回复、`/following` 收录、抽取权重 |
| 基本生活 | 对应人物、年龄、职业、地区、作息；没有依据的留空 |
| 兴趣与性格 | 具体关心什么、熟悉到什么程度、什么会吸引或消耗注意力 |
| 表达与发言 | 为什么公开说、说给谁听；什么会使他展开、反驳或潜水，别人怎样回他才继续 |
| 关系与知情 | 认识谁、从哪里知道什么；不能由维护者知道替代人物知道 |
| 近期状态 | 已有前情与实际进展，不是每轮都要改写成帖子的任务清单 |
| 示例与备注 | 按此人需要示范接话、展开或短反应；例句不等于已发生事件，不统一长度和句式 |
| 事实依据 | 「原典」「推演」「待定」及来源，保持确定性区别 |

开关填「是/否」；AI 范围填「关闭/仅样例/日常」；资料状态填「样例/已审核」。抽取权重 0–10，0 暂不抽取。作品人物与路人按账号类型分池，作品来源和 `/following` 仍是独立设置。

表达习惯写具体情境，例如“做法被质疑时会逐步解释；只被夸奖时回一句”。统一参考方法见[社交媒体参考](../docs/social-reference.md)。

作品人物在「对应人物」中注明原作称呼，原典接入见[档案与上下文](../docs/private-profiles.md)。头像填 `users/本人ID/avatar.svg`（也支持 png、jpg、webp），留空时不使用头像。

已有账号不改稳定 ID，不回收旧 ID 给另一个人；网名和简介可改。人物潜水不必停用，有历史帖子的用户需要退出时关闭账号，保留其档案与历史。

## 补充与新增

额外关系、经历、发言参考可放在同一文件夹的其他 `.md` 文档或子文件夹中，AI 读取该用户时一起读取；按需添加，不预建空文件。运营入口见 [AI 总控](../docs/ai-updates.md)。

新增时复制 [空白模板](TEMPLATE.md) 到 `users/新ID/profile.md`，填写与文件夹相同的 ID。ID 为 2–64 位小写字母、数字、连字符；用户名为 2–32 位小写字母、数字、下划线，且全站唯一。原创路人同时按[基础档案模板](PERSON_TEMPLATE.md)编写 `person.md` 并登记 `population.json`；不能只替换模板中的职业名。先补齐资料、检查，再按需要开放日常权限；无需先发帖子。

原创的隐情、偏见和不愿自述的动机可以全部放进仓库，标注「作者层」即可；不要伪装成已发帖的事实。作品人物继续按外部原典机制处理，本次不为他们添加基础档案。

## 编辑与更新

保留固定章节与表头。列表每项用 `- `，表格里的竖线写 `&#124;`，换行写 `&#10;`；自由备注可直接写多段 Markdown。大段补充放备注或附加文档，不另造表格字段。

本机运行 `npm run social:build` 更新目录和网页数据；提交到 `main` 后，资料同步工作流会自动完成同样的工作。分支改动合入后才更新正式网站，`Y29_EDIT_BRANCH` 可指定预览总表的编辑分支。

修改年龄、职业、性别或居住范围时同步基础档案与主档案中的镜像；`population.json` 的年龄、性别、教育、家庭和权重也要对应。更新快照日期与必要的变化依据，再运行 `npm run check`。不因年份跨越自动加岁，不把成长分支当已经实现。
