# 人物账号管理

管理入口是本目录的 [`registry.json`](registry.json)。它是可手工编辑的唯一公开账号来源。遵循 GSM 的稳定身份原则，账号的 `id` 与显示名称分开，不在发帖时随机选择作者。

| 字段 | 规则 |
| --- | --- |
| `id` | 2–64 位小写字母、数字、连字符；永久身份，有历史后不能删除或另配人物 |
| `handle` | 2–32 位小写字母、数字、下划线；公开显示名，全站唯一 |
| `name` | 显示昵称，改名不会改变历史归属 |
| `bio` | 公开简介，不能放完整人设、秘密或管理说明 |
| `avatar` | `assets/avatars/` 下的固定图片路径，首次分配后不会自动重画 |
| `enabled` | 是否允许新增内容；关闭仍保留头像、主页和旧帖 |
| `aiScope` | `none` 不由 AI 发言；`sample` 仅样例；`daily` 经授权的衍生日常 |
| `profileStatus` | `sample` 样例简介；`approved` 经过作者审定的公开简介，不表示私有资料也能公开 |

首版所有账号都为 `sample`，总开关 `automaticPosting` 为 `false`。两者独立；将一个用户改成 `daily` 不会启动自动任务。

## 日常维护

1. 新账号：复制一条登记，选择未用过的稳定 ID 和 handle，放入审核过的头像，再写公开简介。新增必须与首帖一起通过校验，不能先用未注册作者发帖。
2. 改名、简介、头像：只改登记，执行 `npm run social:build`，所有旧帖同步新显示资料。头像文件必须在本项目内，不接受外部 URL 或指向私有目录的链接。
3. 暂停：设 `enabled: false`；导入器阻止新帖，构建保留历史。恢复设为 `true`。
4. 作者保留账号：`aiScope: "none"`。运营任务不能修改其公开登记、私有档案或正文。
5. 已有历史不能删除账号；校验会阻止孤立帖子。不要回收 ID 给另一个人物。

## 人设与知情范围

**不要把人物私有管理说明写在这个公开文件中。** 表达方式、发布习惯、人物关系、知情范围、事实来源和【原典】【推演】【待定】在[仓库外档案](../docs/private-profiles.md)维护。公开简介与内部设定是两条不同的资料路径。

原典的确定性与是否适合公开是两件事：即使标为【原典】，秘密也不能写进公开档案或帖子。推演与待定项只能供讨论，不能自动升格为事实。当前简介、图形头像和样例对白都是界面演示，不构成已审定人设。

公开发生的长期小事如有必要沉淀到 `docs/community.md`，带上帖子 ID；只写公开可见的事实，不复述人物内心、私有关系或未发生的计划。
